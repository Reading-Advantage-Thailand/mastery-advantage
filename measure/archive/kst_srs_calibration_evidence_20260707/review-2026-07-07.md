## Code / spec quality observations

- **Estimators are documented with alternatives:** each decision log entry explains why the chosen option beat alternatives (e.g., Wilson over Beta bound for auditability; stratification over logistic covariate for zero infrastructure).
- **Provenance and release gating are consistent:** both §12.10 fitted parameters and §6 edge calibration require human review before application, avoiding silent drift.
- **Worked examples cover edge cases:** E1a shows chance MC performance reading as zero proficiency; E1c shows 5/5 cannot reach `high` confidence; E4 shows lucky single pass contained.
- **Cross-track integration is clean:** §11.2 reuses §13.1 guess correction and §11.4 seeding contract; §12.10 references §15.2 adapter declarations.

## Risks or blockers

1. **Pedagogy review deferred.** The approval record notes constants (retention targets, hint/reveal caps, half-life 10, tercile banding) are folded into the shared curriculum-review tech debt. These directly change learner-facing labels and review frequency.
2. **Evaluation harness is contract-only.** §17 specifies metrics and thresholds, but no implementation or fixture code was added in these commits. Until a reference harness exists, "bulletproof" is not mechanically verifiable.
3. **Per-learner FSRS fitting and logistic ability models are explicitly deferred.** This is documented scope, but high-variance populations may still see poor fits until these future stages land.
4. **Downstream consumers must adopt guess floors and age-band declarations.** Adapter interfaces change; domains without declared guess floors will default to `g = 0`, which is correct for free response but dangerous for MC-heavy domains that forget to declare `g = 0.25`.
