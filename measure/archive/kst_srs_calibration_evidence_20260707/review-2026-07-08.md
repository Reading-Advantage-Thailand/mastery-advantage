## 3. Code quality observations

- **Estimator choices are justified:** Wilson lower bound was chosen over a Beta posterior for auditability; closed-form arithmetic is shown in `examples.md`.
- **Small-sample guardrails:** n<3/n<6 confidence caps prevent premature proficiency labels.
- **Determinism and provenance:** Fitted parameter artifacts require human-reviewed release and version stamping; synthetic fixtures avoid real learner data.
- **Approval gap:** Like the core track, pedagogy review was by owner directive, with constants folded into tech debt.
- **Volume gate may be steep:** The ≥10,000 reviews / ≥100 students gate could leave small domains on defaults for a long time. This is acknowledged with the fallback hierarchy, but real-world feasibility is unverified.

## 4. Risks or blockers

- **Pedagogy ratification outstanding:** Retention targets (0.95/0.90/0.80), hint/reveal caps, recency half-life 10, and tercile banding need human review.
- **Ability adjustment simplicity:** Tercile stratification is a pragmatic starting point but may miss continuous ability effects; the spec documents this as a future stage.
- **Evaluation harness is contract-only:** No actual simulator or replay tooling exists in this repo; downstream implementations must build it.
- **Real-data validation absent:** Worked examples are synthetic. The Wilson and recency arithmetic should be validated against empirical response patterns before release.
