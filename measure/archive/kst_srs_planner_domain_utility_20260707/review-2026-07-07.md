## Risks or blockers

1. **Pedagogy review deferred.** The approval record notes constants (term weights, 0.7/0.3 sparse split, diversity cap 2, `loadBudgetFactor` 0.8, ±5% fuzz) are folded into the shared curriculum-review tech debt. These directly shape what learners see next.
2. **Dependency on `frequency_semantic_ranking_layer_20260611`.** The planner contract is complete, but no reference English frequency provider exists yet. Until that track adopts the `UtilitySignal` schema and ships a provider, the `utility` term is inert in vocabulary domains.
3. **Review-load budget is a planner-level throttle, not a queue-level guarantee.** §10.5 can recommend 0 new skills, but the actual daily queue is still bounded by `maxReviewsPerDay`; load smoothing helps but does not eliminate clumping if a large cohort of cards becomes due simultaneously.
4. **No runtime implementation.** Like the other two tracks, the v3.2 deliverable is specification only; consuming apps must implement the provider, sparse-mode flag, and queue composition rules.
